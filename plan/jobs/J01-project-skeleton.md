## Spec

**Project settings.** Physics interpolation on. Physics tick 60. Window 1600 × 900, stretch mode `canvas_items`, aspect `keep`. Rendering: Forward+, MSAA 2×. Collision layer names: 1 world, 2 player_body, 3 enemy_body, 4 player_hurtbox, 5 enemy_hurtbox, 6 player_hitbox, 7 enemy_hitbox, 8 projectile, 9 interactable, 10 world_item.

**Input map.** Actions: `move_up` W, `move_down` S, `move_left` A, `move_right` D, `attack_basic` LMB, `skill_1` RMB, `skill_2` key 1, `skill_3` key 2, `dodge` Space, `interact` E, `inventory` I, `character` C, `journal` J, `pause` Esc, `debug_console` F1, `debug_cycle_weapon` Tab.

**Autoloads.** `EventBus` declares the signals other jobs will emit. Start with: `enemy_died(enemy: Node)`, `player_died`, `item_picked_up(item)`, `quest_updated(quest_id: StringName)`, `quest_completed(quest_id: StringName)`, `flag_set(flag: StringName)`, `world_state_changed(state: int)`, `zone_entered(zone_id: StringName)`, `dialogue_started(npc_id)`, `dialogue_ended(npc_id)`. Later jobs add to this file; keep it the single list. `GameState` holds `phase: int = 1`, `flags: Dictionary`, `set_flag(name)`, `has_flag(name)`, `current_zone: StringName`, and emits `flag_set`. `WorldState` holds `enum State { DAY, FOG }` and `state` with a setter that emits `world_state_changed`; the rest is J11. `SaveSystem` is an empty class with `save()` and `load()` returning false; J19 fills it.

**Palette generation.** `tools/gen_palette_gd.ps1` reads `design/palette.json` and writes `game/core/palette.gd` containing: `const DAY: Dictionary` and `const FOG: Dictionary` mapping role name to `Color` for ramp, environment, accents and UI signals; `static func role(name: StringName, state: int) -> Color` that falls back to DAY when a role only exists there; and a header comment "generated, do not edit". Re-running the script must be idempotent. Add the command to `game/README.md`.

**Graybox kit.** Materials as `.tres`: `mat_gray.tres` (palette day ramp mid), `mat_frost.tres` (fog lichen tint), `mat_highlight.tres` (day sun), `mat_rarity_common/fine/rare/legendary.tres`. Scenes: `box_actor.tscn` (MeshInstance3D BoxMesh plus a smaller nose box on -Z (Godot forward, so `look_at` and `Vector3.FORWARD` agree with it), `@export var size_class` with an enum PLAYER, SMALL, MEDIUM, LARGE, BOSS, TROLL applying the sizes from the gdd placeholder policy), `box_prop.tscn` (box with StaticBody3D collision), `ground_plane.tscn` (PlaneMesh 60 × 60 with StaticBody3D). A `Graybox` static helper with `func make_box(size: Vector3, material) -> MeshInstance3D`.

**Test arena.** `game/test/arena.tscn`: ground plane, a dozen props as walls and pillars, DirectionalLight3D at 45° with the day sun colour, WorldEnvironment with ambient from palette day sky, a `Marker3D` named `PlayerSpawn`. It runs and shows a lit gray scene.

**GUT.** Install GUT compatible with Godot 4.7 into `game/addons/gut`, enable the plugin, set the test directory to `res://test/unit`, add `test_example.gd` asserting `Palette.DAY.has("moss")`.

**Git.** If the repo root is not yet a git repository, `git init` it on branch `main`. If it already is (the design and plan may have been committed before this job), work on a branch `job/J01-project-skeleton` and merge to `main` when done. Either way make sure `.gitignore` contains `game/.godot/`, `game/export/`, `*.tmp`, `.DS_Store`, `Thumbs.db`, and keep `*.import` files tracked. Commit message "J01: project skeleton".

## Notes for later jobs

- Add new signals to `EventBus` rather than wiring nodes directly.
- Use `Graybox.make_box` and the kit materials for every placeholder.
- Give every signal parameter a type, also where a job spec writes it without one (J07's `enemy_spawned(enemy)`, J15's `quest_started(quest_id)`). An untyped declaration does not compile; write `Variant` while the payload is undecided.
- `Palette.role(name, WorldState.state)` works for every role in either state. An accent that only one state has (`ember`, `spirit`, `sun`) comes back from that state.
- `--check-only` reports an error for every script that reaches an autoload. `plan/README.md`, Godot from the command line, says what to run instead, and that a script nothing loads is not checked at all.

## Deviations

- **GUT 9.7.1 from tag `v9.7.1` (the `godot_4_7` branch), not the default branch.** `main` is 9.6.1 and declares Godot 4.6.x as its only supported range; 9.7.1 is the release for 4.7.
- **Nose box on -Z, not +Z.** -Z is Godot's forward (`Vector3.FORWARD`, where `Node3D.look_at` and a `Marker3D`'s forward point; J02's aim and J12's entry markers rely on that). A +Z nose would face away from everything the engine calls forward. The spec sentence above was corrected.
- **`Palette` is a `class_name` static class, not an autoload.** `plan/README.md` listed palette among the autoloads; a `const` plus a `static func` need no node, `Palette.DAY` works through the class name, and an autoload sharing its name with a `class_name` is a GDScript error. The README layout line now says so.
- **Autoload scripts and GUT test scripts have no `class_name`.** Autoloads for the same reason; test scripts because GUT finds them by file name, so a global class per test file adds nothing. `plan/README.md` says so in its Decisions row and in a convention line. Every other script under `game/`, outside `addons/`, has one.
- **"46 distinct hex values".** `design/palette.json` holds 44 distinct colours (6 ramp + 12 environment roles × 2 states, plus 3 + 5 accents; the UI signals reuse those). The generator writes each role's usage note as a trailing comment, and the sky note names two more hexes (`#B5D2EE` day horizon, `#6F6A85` fog dusk), so `palette.gd` contains 46 distinct hex strings, 44 of them `Color` constants. The number in the criterion presumably counted those two; nothing was invented to reach it.
- **`GameState.set_flag` emits `flag_set` only the first time a flag is set, and `WorldState.state` emits only when the value changes**, so listeners never double-fire. The parameter is named `flag` rather than `name` because `name` shadows `Node.name`.
- **`SaveSystem.save()` and `load()` keep the spec names.** Verified in 4.7 that a method called `load` raises no shadowing warning; the class comment tells J19 to use `ResourceLoader.load()` inside that script.
- **`Graybox` also owns the `SizeClass` enum, the `SIZES` table and `MAT_*` preloads of the seven kit materials**, so later jobs refer to materials by constant instead of by path. `BoxActor` exposes `body`, `nose`, `material` and `get_body_size()`; `BoxProp` exposes `size` and `material`, origin at the bottom centre, layer 1. Both scripts are `@tool` so size and material changes show in the editor. Each node copies its mesh and shape in `_ready()`, so no two nodes share them, whether they come from `instantiate()`, `Node.duplicate()` or Duplicate in the editor. The sub-resources are also `resource_local_to_scene`, but that alone only covers `instantiate()`: a duplicate is handed the original's resources. The root of the scene open in the editor skips the copy and keeps the sub-resources it was saved with, so saving a kit scene does not rewrite them.
- **The arena has a `Camera3D`** at the GDD's 55° pitch so `tools/run.cmd` shows the scene before J02 adds the camera rig, which replaces it. The arena also lines up the six size classes as `BoxActor`s next to the twelve props.
- **Kit materials and the arena's light and environment carry literal palette values**, because a `.tres` or `.tscn` cannot read a script constant. The role behind each value is tabled in `game/README.md`.
- **`tools/test.cmd` exists already** (J21 lists it) because every job from here runs GUT. `game/.gutconfig.json` holds the test directory for the command line. The GUT editor panel reads only `user://gut_temp_directory/gut_editor_config.json`, which no repository file can supply, and runs nothing while that file names no directory. `tools/gut_panel_setup.cmd` writes the directory into it once per machine: it runs `tools/gut_panel_setup.gd` headless, which goes through GUT's own config class. It has been run on the development machine, and `game/README.md` documents it.
- **`.gitattributes` gained `*.cmd text eol=crlf`**: the existing `* eol=lf` rule would check the batch files out with LF endings, which `cmd.exe` mishandles.
- **Jolt is set explicitly** (`physics/3d/physics_engine="Jolt Physics"`) so the plan's decision holds whatever the engine default is.
- **Every `EventBus` signal parameter is typed.** The spec writes `item_picked_up(item)`, `dialogue_started(npc_id)` and `dialogue_ended(npc_id)` as shorthand. `item` is `Variant` until J06 decides what it carries; `npc_id` is `StringName` like every other id (J16 adds `npc_talked(npc_id: StringName)`).
- **An untyped declaration is a compile error.** `project.godot` sets `debug/gdscript/warnings/untyped_declaration` to Error, so the static-typing decision is checked by `--quit` and GUT instead of by eye: a script with an untyped variable, parameter, return value or signal parameter prints `SCRIPT ERROR: Parse Error: ... (Warning treated as error.)`. Godot's default directory rule exempts `res://addons`, so GUT is unaffected, and GUT's doubles still work.
- **`Palette.role` falls back in both directions.** The spec names only the fallback to DAY. The fog accents (spirit, wisp, rune, ember, dusk) are needed while the state is DAY (J11's cairn and cave lights, J17, J20), and asking for them by day returned magenta with an error. A role that only one state has now comes back from that state whichever one is asked for.
- **The `--check-only` line in the `plan/README.md` cheat sheet gained a caveat.** It compiles its script before the autoloads exist, so it reports `Identifier not found` for every script that reaches one. The cheat sheet now says so, lists how to run one scene for one frame, and notes that the headless runs only compile what they load.
- **`test/unit/test_graybox.gd` and `test_core.gd` were added next to the example test.** Instantiating the kit scenes headless is the only way to prove the `@tool` sizing and that instances and duplicates own their meshes without the editor, and the core test pins the flag and world-state signalling that every later job leans on (including int and dynamic assignments to `WorldState.state`, which J19 will make).
- **Not merged to `main` by this job.** The gauntlet's gate step does the merge, so the last acceptance criterion is left to it.
